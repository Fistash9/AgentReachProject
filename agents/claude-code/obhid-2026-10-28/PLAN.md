## 4. Т2 і цей хук: один чи два (відповідь на доповнення координатора)
- **Рекомендація: один файл хука «момент збою», дві гілки** (delegate/deepseek — Т2 як спроєктовано; Bash — покажчик рецептів + Т2 для класів середовища). Причини з даних: (1) Т2 ще не застосовано (BACKLOG.md:25), тож об'єднати зараз дешевше, ніж мігрувати потім; (2) фільтр «що є збоєм» (110 з 271 is_error — не збої) якраз той, якого бракувало Т2 для Bash; (3) момент Т2 — PostToolUseFailure — бачить 4 з 13 K, тож для Bash у будь-якому разі потрібна реєстрація й на PostToolUse; чинні PostToolUse/Failure зареєстровані лише для delegate|deepseek (+baton_pick_up, AskUserQuestion), на Bash — жодного, тож процес на Bash-виклик додається один у будь-якому варіанті; (4) спільні пороги й тексти Т2 (2-й → «стоп: гіпотеза», 3-й+ → «інший підхід або питання користувачу») збігаються з ідеєю obra «≥3: stop and question the architecture».
- Відмінності, які треба тримати: ключ серії для delegate — інструмент, для Bash — клас сигнатури (Bash один на все); логер делегата не повинен ламатися через Bash-гілку (fail-open, окремий try/except, тести в обидва боки); Т2-стоп для own-типу (49 подій) у Bash-гілку НЕ брати — у Т2-бектесті Bash «наосліп» лише 5 з 17.
- Альтернатива (не рекомендую): окремий файл лише для Bash з імпортом констант Т2 — той самий один процес на виклик, але дві копії логіки серій.

## 6. Рекомендація і проба
- **Варіант (в) поетапно, перший етап — дані.** Причина одним реченням: 9 з 13 випадків з відомим рецептом — «м'які» (код 0), тож їх не бачить ні Т2-момент, ні чинний PreToolUse, а 79% повторних збоїв середовища (50 з 63) рецепта ще не мають — потрібні і хук за ВИВОДОМ, і цикл «дописати рецепт».
- **Крок 0 (дані, без хука; потребує рішення користувача: TROUBLES/install-check — файли правил):** 0.1 зняти по 1 реальному payload PostToolUse і PostToolUseFailure для Bash (логер на копії) — критерій: надруковано по записі, поля `tool_response` Bash відомі (зараз НЕ ПЕРЕВІРЕНО: дока каже «схема залежить від інструмента», у jsonl хук-вхід не пишеться); 0.2 append-only блок покажчика `ERR: клас | шаблон рядка | шаблон команди → заголовок` на 5 класів з рецептом — критерій: 13/13 K відтворюються тест-входами; 0.3 рецепти для повторних класів без запису (/tmp 9, file 7, eval-EOF 3, jq 2, /proc 2), кожен з пробою (НЕ ПЕРЕВІРЕНО, що `pkg install file` потрібне чи працює) — критерій: ≥3 з 5; 0.4 install-check: `npx <пакет> add|install` — критерій: тест-вхід E3 показує картку.
- **Крок 1 (тінь, 10 сесій або 1 000 Bash-викликів — що пізніше; ≈4 доби при 2,5 сесії/добу):** хук лише пише в `.claude/logs/failure-moment.jsonl`, нічого не вкидає. Критерії: спрацювань ≤10 на 1000 (бектест 6,1); хибних ≤10% за ручною перевіркою всіх (бектест 1 з 36); затримка ≤100 мс (бектест 53/69); 0 падінь (fail-open); позитивні 13/13 і негативні ≥100 (168 own + 110 не-збоїв з бектесту) у hooks-smoke.
- **Крок 2 (живий режим, 10 сесій ≈4 доби):** вкидання ≤2 за кожну сесію, кожне з `шлях:рядок`; частка вкидань з рецептом, після яких у наступних 4 викликах є рецепт-маркер чи відкриття запису, ≥50% (бектест-база міжсесійних K: 5 з 11 = 45% без підказки на помилку); 0 «наново» для класів з рецептом (бектест 2 з 11); для кожного класу, що впав ≥2 рази без рецепта, рецепт записано ≤1 сесії потому (бектест: /tmp 9 подій, 0 рецептів). База: 1 міжсесійний K на 9,5 сесії, тож за 10 сесій очікується ≈1 — якщо вкидань з рецептом 0, пробу подовжити ще на 10 сесій, а не робити висновок.
- Правило відмови: у тіні спрацювань >10 на 1000 або хибних >10% — вимкнути (прибрати 2 записи settings.local.json; .bak є), покажчик лишається.
- **Premortem:** якщо проба провалилась — бо збої з відомим рецептом трапляються раз на ~10 сесій, а нові класи без рецепта з'являються швидше, ніж їм пишуть рецепти (хук мовчить, покажчик застарів), або бо поля payload PostToolUse Bash не збіглись з припущеними і хук (fail-open) мовчить усі 10 сесій — тому крок 0.1 першим.

## 7. Що не вдалося виміряти / обмеження
1. Точні поля `tool_response` Bash у PostToolUse — не перевірено (див. 0.1).
2. Час народження рецепта = коміт (нижня межа); для E1 це 2 хв після першої помилки.
3. Доля K — евристика і читання 4 наступних викликів; K=13 — мала вибірка, статистики нема. Лічильник «відкрив/grep TROUBLES у наступних 8 викликах: 8 з 13» (backtest-out.txt, stage3) рахує і записи в TROUBLES, тому в аналіз не взято.
4. 13/13 і 0 пропусків прототипа — на тих самих даних, з яких складено індекс (резубституція); незалежна оцінка — лише крок 1–2.
5. Ціна повторного винаходу виміряна лише для E3; ціну для користувача журнали не містять.
6. Не входять журнали DSH і інших проєктів; own-тип «м'які» (NOFILE 70, TRACEBACK 31) вручну на хибні не перевірено (вибірка 7+7: навмисні проби/власні помилки) — на хук не впливає, на N впливає.
7. Рецепти для порожніх класів не перевірялись (/tmp, file, eval-EOF, jq, /proc).
8. Клас E3 ключем-текстом не знаходиться; у покажчику потрібна умова на команду (`npx|node|npm`) — у прототипі це зроблено вручну.
9. Часи в журналах UTC, коміти +0300/+0200 — зіставлено в epoch.
