## Коротка відповідь

Три речі ламають v0 ще до Stop-хука: `--out` за замовчуванням **усередині репо** (`.claude/logs/`) → наступний `git status` бачить власний журнал → «не закомічено» росте саме від хука; `l[3:]` без `core.quotePath=false` і без обробки `R old -> new` → `changed` бреше на кирилиці й перейменуваннях; `prev_hash` читає весь файл і не має лока → паралельні сесії роздвоюють ланцюг. Логіка полів правильна, «не виміряно» зроблено чесно — але `anchor` при `t0=None` віддає `value: None`, і це діра в тому самому правилі.

*Цього разу не шукав — це рев'ю вашого файлу. Твердження нижче — вивід із коду; де я не певен поведінки git/Python, позначено [не перевірено].*

## 1. Баги й краї

**1.1 Самозабруднення (найгірше).**
```python
out = a.out or os.path.join(cwd, ".claude", "logs", "turn-state.jsonl")
```
Хук пише в репо → наступний прогін `git status --porcelain -uall` побачить цей файл → «Не закомічено файлів: N+1» → агент комітить журнал → далі росте на кожному ході. Класичний «зелений рядок, що бреше» навпаки — червоний, який бреше. Мінімум: `out` поза `cwd` (`$HOME/.claude/logs/…`) **або** перевірка на старті, що `out` є в `.gitignore`, інакше `exit 0` без запису + `systemMessage: "журнал не заігнорений"`.

**1.2 `changed` — кирилиця й перейменування.**
```python
sorted(l[3:] for l in git(cwd,"status","--porcelain","-uall").splitlines() if l)
```
- За замовчуванням `core.quotePath=true` → `звіт.md` виходить як `"\320\267\320\262..."` → `l[3:]` дає екранований рядок → пізніше `os.path.basename(p) not in names` ніколи не зійдеться → `tmp_not_saved` хибно росте.
- `R  old -> new` → `l[3:]` = `old -> new` одним «шляхом».
```python
git(cwd, "-c", "core.quotePath=false", "status", "--porcelain", "-uall", "-z")
# split("\0"), парні записи R/C: перший — джерело, другий — ціль
```
`-z` і `split("\0")` знімають обидві проблеми разом; на перейменуваннях треба зсув на 1 (два NUL-поля на один запис). [не перевірено, чи не знадобиться `--no-renames`, якщо простіше]

**1.3 `anchor` при `t0=None` порушує власне правило.**
```python
field(lambda: (git(cwd,"rev-list","-1",f"--before={t0}","HEAD").strip() or None) if t0 else None, ...)
```
`None` — не `"не виміряно"`, тому `unm` у `summary()` його **не покаже**, а `error` не буде. Те саме з `rev-list` → порожній stdout (репо створене після `t0`) → `.strip() or None` → тихий `None`. Фікс: у `field()` будь-`None` → `{"value":"не виміряно","error":"порожньо: …"}`.

**1.4 `trees/` — тільки `*.md`, тільки перший рівень, без `with`.**
```python
for n in sorted(os.listdir(tdir)):
    if n.endswith(".md"): trees += open(...).read()
```
Нема `trees/` → `RuntimeError` → `commits_without_node: "не виміряно"` — **це правильна поведінка**, залишити. Але: підтеки ігноруються (`trees/2026-10/x.md` не полічиться), дескриптори течуть, і на 200 файлах це секунди. Замініть на один `git grep -F -l <hash> -- trees/` на весь список комітів або `git grep -F <hash> -- trees/` один раз і мапа «хеш → файл:рядок» (див. 2.1).

**1.5 `tmp_not_saved` — три тихі хибні.**
```python
RE_TMP_MD = re.compile(re.escape(TMP) + r"[\w./-]+\.md")
```
- Пробіл у назві → матч обривається на пробілі → `isfile` False → файл **не порахований** (хибне «зелено»).
- `names` = усі basenames репо: два різні `REPORT.md` в різних теках → «збережено», хоча збережено інший.
- `os.path.isfile(p)` — файли в `$PREFIX/tmp` зникають (Termux чистить) → поле тихо меншає між прогонами.
```python
# 1) шлях до пробілу/лапки, 2) порівнювати вміст, не basename, 3) рахувати окремо
return {"found_in_log": len(seen), "still_exists": sum(map(os.path.isfile, seen)), "unsaved": sorted(...)}
```
Порівняння вмісту: `sha256` tmp-файлу проти множини хешів файлів репо (будується з `git ls-files -z` + `status -z`, не `os.walk` — див. 3.2).

**1.6 `measured_at` — не час вимірювання.**
```python
return t1, fields   # → record(session, measured_at=t1, ...)
```
Це останній таймстемп транскрипту. Для `--recheck` і для аудиту «коли пораховано» це різні речі. Додайте `measured_at: datetime.now(timezone.utc)` **і** `last_event_at: t1`.

**1.7 Крихкий канон хешу.**
```python
body = json.dumps(rec, ensure_ascii=False, sort_keys=True)
... f.write(json.dumps(rec, ensure_ascii=False, sort_keys=True) + "\n")
```
Рахується тіло **без** `hash`, пишеться **з** `hash` — верифікатор мусить знати це правило. Плюс залежність від дефолтних `separators=(', ', ': ')`: будь-який майбутній запис із `separators=(',',':')` розірве ланцюг, і виgalдатимете це як «підробку». Зафіксуйте:
```python
CANON = dict(ensure_ascii=False, sort_keys=True, separators=(",", ":"))
```
і додайте режим `--verify`, який іде по файлу, перевіряє `prev_hash` і перераховує `hash` — без нього ланцюг не працює, бо його ніхто не перевіряє.

**1.8 `read_transcript` без стелі.**
Транскрипт 50 МБ + `json.dumps(r)` на кожен запис **на кожен Stop** = секунди на Termux. Індекс: поруч `.idx` з `{size, mtime, offset, знайдені tmp-шляхи}`; читати лише новий хвіст. Те саме для `last_hash(out)` — читати останні 8 КБ через `seek`, а не весь файл.

**1.9 Дрібне.** `session = os.path.basename(tpath).split(".")[0]` → `None`, якщо `--hook` без `session_id` (треба fallback на basename). `open(__file__)` без `with`. `except Exception` у `main` пише `systemMessage`, але **не пише рядок у журнал** — діра виглядає як «даних нема», а не «впало»; пишіть `{"fields":{"error":…}}`.

**1.10 Репо без комітів.** `git rev-list -1 HEAD` → `fatal: ambiguous argument` → `RuntimeError` → `anchor: "не виміряно"`, `commits: "не виміряно"` — коректно. Але `tmp_not_saved` при цьому відпрацює й покаже число → читач бачить «не виміряно» і число поруч. Це ок, якщо `error` у полі є (є).

## 2. Чи підробка — дописати хеш у дерево

**Мій висновок: це не підробка поля, а підробка сенсу — і тому поле не можна показувати як «вузол записано».**

- Поле чесно міряє «рядок `hash` присутній у `trees/*.md`». Дописати хеш — зробити поле правдивим. Але ви хотіли міряти «текст вузла написано разом із комітом», а міряєте «хеш десь є». Це та сама пастка, від якої застерігали на нараді.
- Найдешевший сигнал «дописано заднім числом» — **коли** файл дерева торкався останній раз відносно коміту:
```python
# для коміту c і файлу f, де знайдено хеш:
touch = git(cwd, "log", "-1", "--format=%h", "--", f).strip()
late  = git(cwd, "merge-base", "--is-ancestor", c, touch)  # touch — нащадок c?
"evidence": {"file": f, "line": n, "file_last_commit": touch, "added_after_commit": rc == 0}
```
Тоді поле стає `commits_without_node` + `commits_with_node_added_later`, і друге — це і є «зелений рядок, що бреше», показаний як червоний.
- Друге: поки `turn-state.py` аудитує агента, який сам пише в `trees/`, будь-яке «є/нема хешу» — циркулярне. Тримайте це поле як **підказку для людини**, а не як критерій проби (критерій — 6. `V_turn`/`V_later`).

## 3. Що змінити до Stop-хука

**3.1 Бюджет часу.** Зараз на хід: 3 `git` (до 30 с кожен) + `os.walk` усього репо + читання всіх `trees/*.md` + читання всього `out` + парсинг усього транскрипту. Дефолтний таймаут хука — 60 с [з доків, цитовано раніше]; на Termux flash повільний. Ставте `"timeout": 20` у settings **і** міряйте:
```python
t_start = time.monotonic(); ...
rec["duration_ms"] = int((time.monotonic()-t_start)*1000)
```
Якщо `duration_ms > 5000` — це баг, а не «повільно».

**3.2 Прибрати `os.walk`.** Заміна на git (швидше і gitignore-aware):
```python
names = {os.path.basename(p) for p in git(cwd,"ls-files","-z").split("\0") if p}
names |= {os.path.basename(l[3:]) for l in ...status -z untracked...}
```

**3.3 Паралельні сесії — ланцюг роздвоюється.**
Дві сесії читають той самий `last_hash` → обидві пишуть `prev_hash=X` → два «нащадки». Варіанти, за зростанням складності: (а) файл **на сесію** `turn-state.<session_id>.jsonl` (рекомендую — ламає лише глобальну нумерацію, ланцюг лишається лінійним); (б) `fcntl.flock(out, LOCK_EX)` навколо «прочитати останній → дописати» [не перевірено на Android fs]; (в) лишити як є, але тоді `--verify` мусить знати про DAG і не кричати «розрив». Не робіть (в) — ви не будете це підтримувати.

**3.4 Не ставити `async: true`** (інакше `systemMessage` не показується користувачу — підтверджено докою в минулому ході; у вас уже перевірено, що видно).

**3.5 Коли почне блокувати** — перший рядок `if inp.get("stop_hook_active"): sys.exit(0)`, інакше цикл.

**3.6 Дрібниця, яка вб'є довіру:** `--hook` без `transcript_path` зараз дає `systemMessage: "не виміряно (…)`" — добре; але якщо транскрипт є, а `git` падає (напр. `proot` без git у PATH), ви отримаєте три «не виміряно» **без жодної підказки**, що саме. У `error` вже є текст — виводьте перший `error` у `systemMessage` одним рядком.

## Червоні прапорці

- `--out` у репо — це баг, який **уже** впливає на ваш вимір 14 незакомічених: перевірте, чи `.claude/logs/turn-state.jsonl` не в тих 14.
- «3 з 4 без вузла — правда» — так, але `without_node` не розрізняє «текст без хеша» і «текст із хешем, дописаним після». Поки цього нема, поле неaudитоване.
- `commits: [l for l in out.splitlines() if l]` — роздільник `%h %s` через пробіл: тема коміту з кирилицею виживе, але `%s` з новим рядком у темі (можливо через `-m` з кількома `-m`) — ні.

## Чого не знайшов

- Поведінку `git rev-list --before=<ISO з 'Z'>` саме з суфіксом `Z` у вашій версії git — [не перевірено]; якщо якір колись поїде, перший підозрюваний — тут. Безпечніше: `--before=<t0>` + лог `anchor_commit_date` у записі, щоб розбіжність була видна.
- Чи `fcntl.flock` надійний на Android-сховищі Termux — [не перевірено].

**Рекомендація (висновок, не факт):** спершу 1.1, 1.2, 1.3, `--verify`, `out` поза репо і `timeout: 20` — це 5 правок, після яких v0 можна вішати на Stop. `trees/` і `tmp_not_saved` лишити «не виміряно» до v1, щоб не показувати число, якому самі не вірите.
