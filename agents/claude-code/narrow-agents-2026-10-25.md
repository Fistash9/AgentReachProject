## 2. Що в ідеї нового порівняно з цим

1. «Роїння» в записах — відповідь на «старт дорожчає», вихід за рамки породжує агента. Ідея користувача інша: агента створює задача, на старті він бере лише потрібне.
2. Підтягування «по гілках дерева». У записах дерево є пам'яттю про стан задач; як джерело контексту під-агента (читай лише гілку цієї задачі) воно не описане.
3. Вимір, який у BACKLOG відсутній: токени першого ходу під-агента. Сьогоднішній вимір (див. 3) дає опорне число.
4. У записах два варіанти — окремий вулик або лінивий старт у тій самій сесії. Тут третій: звичайні під-агенти з вузьким визначенням у тій самій сесії (не окремий запуск claude у теці).
5. Голограма стає форматом вхідного пакета для агента (шапка вузла + посилання назад), а не лише записом для людини.

## 4. Як підтягувати по гілках дерева наявними засобами

Що є зараз (прочитано):
- tools/trees-index.py (72 рядки): друкує `файл:ID [статус] назва` для всіх вузлів trees/**/*.md; аргументи — ID (`python3 tools/trees-index.py T5 G2`), фільтр лише за ID, ключ файл:ID, бо ID повторюються між картками. Назви обрізає до 200 символів. Гілки (батько/діти) він НЕ видає: у кортежі лише (id, статус, назва), відступ відкидається. Тіло вузла (done when / evidence) не друкує.

У під-агента Claude він, найімовірніше, не потрапляє як контекст, а лише надсилає в головну — [не перевірено], чи спрацьовує SessionStart у під-агентів.
- «Голограма вузла» як формат: поки лише ідея-картка (derevo-i-golograma.md:1–10; формат вузла G2 — trees/g2/). Окремої команди «дай голограму вузла» немає.

Тому пакет для агента збираємо вручну, оркестратором, до запуску. Конкретно (приклад: вузол Q12 у yakist-roboty-agentiv.md):

1. Знайти вузол: `python3 tools/trees-index.py Q12` → рядок `trees/yakist-roboty-agentiv.md:Q12 [>] …`.
2. Вирізати гілку (вузол + діти за відступом) в окремий файл у тимчасовій теці:
   `awk '/^ *- \[.\] Q12 /{f=1; m=match($0,/[^ ]/); next_indent=m} f&&NR>s&&/^ *- \[/{match($0,/[^ ]/); if(RLENGTH>=0 && RSTART<=next_indent){exit}} f' trees/yakist-roboty-agentiv.md > /data/data/com.termux/files/usr/tmp/branch-Q12.md`
   (скетч, не перевірений; у проби першим кроком — переписати як 15-рядковий tools/tree-branch.py поза git, лише stdlib, або розширити trees-index.py прапором `--branch ID`; правка інструмента — тільки з дозволу).
3. Дописати рядки GOALS.md про ціль і «Зараз» (як це робить tree-focus-hook, goals_lines).
4. Віддати агенту шлях до файлу гілки в промпті; агент сам читає потрібне і, якщо бракує, просить «ще вузол X» через оркестратора (дозволений інструмент: Read, Bash лише для `python3 tools/trees-index.py <ID>`).
5. Підтягування «по факту при потребі»: у промпті одна фраза — «Бракує контексту — не вгадуй: виведи `NEED: <ID або файл>` і зупинись»; оркестратор довантажує і відновлює (SendMessage).

Межа, яку треба прямо назвати: «по гілках» з нашими засобами = ручний або напівручний виріз; автоматичного «дерево → контекст агента» ще немає. Це перший предмет проби.

## 5. Пропозиція проби

Ціль (проєктна): перевірити, що вузький під-агент із пакетом гілки дерева стартує дешевше і не гірше виконує типову задачу, ніж general-purpose, — служить вузлу «роїння» (BACKLOG:1203) і G-голограмі (trees/derevo-i-golograma.md).

Умова: на 3 сесії або 6 задач; нічого не міняти в RULES/hooks/settings; визначення агентів — у пісочниці поза проєктом (правило sandboxes-outside-project-then-promote), промоція лише за рішенням користувача.

Схема (A/B на тих самих 3 задачах, по 2 прогони кожного варіанту):
- A: general-purpose, як зараз.
- B: вузький агент (визначення в `~/tmp/narrow-trial/.claude/agents/`): `omitClaudeMd: true`, `tools: Read, Grep, Glob, Bash`, `disallowedTools: mcp__*`, `maxTurns: 12`, промпт ≤ 400 слів + 3 ключові правила чесності + файл гілки.
- Задачі (типові для нас, лише читання): (1) «знайди в BACKLOG розділ про X і підсумуй у 5 рядках»; (2) «звір число з файлу A з записом у файлі B»; (3) «які вузли гілки Q12 не мають evidence».

Вимірювання (все друкується кодом із журналів агентів, не самозвітом):
1. Токени на старті: usage першого повідомлення (cache_creation + cache_read + input). Опора: ≈26 400. Критерій: B ≤ 8 000 (≈ 30% від опори) [поріг умовний; проставлений до проби].
2. Якість: перевірка результату за заздалегідь записаною еталонною відповіддю для кожної задачі (3 пункти «має бути / не має бути»); критерій: B не гірше A на кожній задачі, 0 вигаданих чисел/цитат (цитати звіряє grep).
3. Кількість кроків: кількість tool_use у журналі. Критерій: B ≤ A + 20% (допустимо трохи більше через ручне довантаження), і ≤ maxTurns.
4. Додатково: скільки разів B вивів `NEED:` (довантаження) — чи достатній пакет гілки; ціль ≤ 1 на задачу.
Проба вважається готовою, коли всі 4 числа надруковані по 6 прогонах і порівняні в таблиці; успіх = критерії 1–3 виконані на всіх 3 задачах.

Крок 0 перед пробою (дешево, без агентів): розкласти 26,4k старту — прочитати перше повідомлення одного журналу (python по полях, кількість символів по блоках), побачити, скільки з них CLAUDE.md-ланцюг. Якщо CLAUDE.md-ланцюг ≪ 20k, критерій 1 переглянути.

Ризики:
- Вузький агент без правил проєкту загублює дисципліну (чесність, українська, формат) — компенсація: короткий блок у промпті; перевірка в критерії 2.
- `omitClaudeMd` залишає managed policy (якщо є) — вплив [не перевірено] у нас.
- git status і описи інструментів лишаються — реальна нижня межа старту може бути вищою за 8k; поріг тоді переглядаємо за кроком 0, а не підганяємо.
- Ручний виріз гілки може помилитись на відступах (формат `▸` у g2/ інший) — тест на двох форматах (`- [x] ID` і `▸ ID`).
- Агент без довантаження застрягне або вгадає: правило `NEED:` і перевірка 4.
- Зайва складність: оркестратор витрачає токени на збирання пакета; критерій — сумарні токени оркестратора + агента, не лише агента (додати до вимірювання 1).
- Хуки: чи діють хуки проєкту всередині під-агента — [не перевірено]; перевірити в пробі одним безпечним викликом, не навмисною порушенням.
