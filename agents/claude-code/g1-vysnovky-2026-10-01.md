# Висновки G1 «голограма в кожній теці/файлі» — на незалежну перевірку
Автор: claude-code, 2026-10-01. Вхідний файл для порівняння трьох шляхів
перевірки (T6, trees/pidrozdil-deepseek.md) — однаковий для A, B, C.

## Питання користувача
Чи варто, щоб кожна тека/файл одразу при створенні мали коротку «голограму»
(карту: що це, звідки, навіщо, зв'язки) для зручної орієнтації агентів і людей?
Чи хтось уже так робить?

## Висновок (що треба перевірити)
Ідея слушна у вузькій формі: не огляд вмісту теки, а короткий «паспорт теки»
(ЩО · ЗВІДКИ · НАВІЩО/ХТО ЗАЛЕЖИТЬ · КОЛИ ПРИБРАТИ) — лише те, чого не видно
з самих файлів. Механізм — хук, не текстове правило. Прямого виміру користі
такого паспорта ніхто не публікував, тому це проба з критерієм, а не доведена
практика.

## Твердження, на яких тримається висновок
1. Claude Code сам підвантажує CLAUDE.md з підтеки, коли агент читає файли в
   ній: «Claude also discovers CLAUDE.md … in subdirectories … included when
   Claude reads files in those subdirectories» (code.claude.com/docs/en/memory).
2. Це діє лише для підтек робочої теки проєкту; тека поза проєктом (~/tmp/…)
   сама не підвантажиться (там само).
3. Стандарт AGENTS.md: «the closest one takes precedence»; у репозиторії
   OpenAI 88 файлів AGENTS.md (agents.md).
4. Дослідження ETH Zurich (arXiv 2602.11988): «providing context files does not
   generally improve task success rates, while increasing inference cost by
   over 20% on average»; «repository overviews … are not helpful»; огляди не
   скорочують шлях до потрібного файлу. Міряли лише кодові задачі
   (SWE-bench Lite 300 + 138 власних); вкладені файли й «походження/причини»
   НЕ вивчали.
5. Документація Claude Code: /doctor вирізає те, що «Claude can derive», і
   лишає «pitfalls, rationale» (там само, memory).
6. Генератор вкладених AGENTS.md hcc (github.com/reyavir/hierarchical-context-
   compressor): 36★, ліцензію не вказано, потрібен OPENAI_API_KEY, пише
   «operational manuals», вимірів користі немає.
7. doc-drift-detector (borghei/Claude-Skills): лише на запит, сповіщень не
   шле; готових інструментів «змінилась деталь → сповістити пов'язані» не
   знайдено.
8. Порадники вкладених файлів (Columbia DAPLab 2026-03-31; гайд AGENTS.md
   baeseokjae) — думки без вимірів.
9. Наш випадок: щоб відповісти «що це і звідки» про дві теки, знадобилось
   8 команд і один хибний висновок; з паспортом вистачило б однієї `cat`.

## Завдання для перевірника
- Перевір кожне твердження 1–8 власним пошуком: ТАК / НІ / НЕ МОЖУ, з URL і
  дослівною цитатою з джерела.
- Шукай докази ПРОТИ висновку: чи хтось виміряв користь (або шкоду)
  паспортів/вкладених README/AGENTS.md/CLAUDE.md, «provenance» тек.
- Шукай готові рішення, яких тут немає: карти тек для агентів, автоматичне
  створення при появі теки, сповіщення пов'язаних частин про зміни.
- Підсумок: висновок тримається / тримається частково / не тримається — чому.
