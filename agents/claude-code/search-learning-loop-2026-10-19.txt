# Інструменти, що перетворюють поправки користувача на постійні правила (огляд, стан на момент пошуку)

**Тип питання:** огляд + рішення (порівняння інструментів). Тому копав глибше за один факт.
**Обмеження звіту:** я вичерпав ліміт кроків пошуку на етапі перевірки зірок/дат останнього коміту для більшості репозиторіїв. Тому там, де дати або кількості немає — прямо пишу «не перевірено», а не вгадую.

---

## Коротка відповідь

Готових інструментів багато (я нарахував ~15 живих проєктів), але вони розпадаються на **три різні архітектури**, і тільки третя відповідає твоєму запиту повністю:

1. **«Capture → CLAUDE.md»** (більшість): хук ловить фразу-поправку, складає в чергу, `/reflect` дописує правило в `CLAUDE.md`. Приклади: `claude-reflect`, `reflexion`, `reflect`, `auto-sop`, `claude-evolve`.
2. **«Lessons-ledger через MCP»**: помилка/фікс пишеться в локальну БД, при наступній схожій помилці підтягується в контекст. Приклади: `learned-experience`, `memories-with-lessons-mcp-server`, `mimir`, `fixmind`, `supermemory-agent`, `misakanet`.
3. **«Повний цикл із перевіркою повтору»** (те, що ти описав): правило має лічильник порушень, підвищується в ранг при повторі й **демотується/видаляється, якщо його ігнорують**. Це вже вміють одиниці: `cc-retrospective-learner` (поріг `pain_count>=3`, ескалація до Hook), `claude-learner` (`record_compliance` + авто-прунінг при ігноруванні >70%), `mimir` (ε-gate: правило приймається лише якщо виміряний приріст > шум), `learned-experience` (`reinforce` з результатом).

**Головне, що варто знати до вибору:** офіційна документація Claude Code прямо каже, що `CLAUDE.md` — це **контекст, а не примус**, і що блокувати дію може лише `PreToolUse` хуок. Тобто будь-який інструмент, який обіцяє, що «помилка більше ніколи не повториться» через дописування в `CLAUDE.md`, продає більше, ніж дає платформа.

> «Auto memory: notes Claude writes itself based on your corrections and preferences… Auto memory lets Claude learn from your corrections without manual effort.»

Обмеження (там же):
> «Both are loaded at the start of every conversation. Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead.»
> «Loaded into | Every session | Every session (first 200 lines or 25KB)»

Тригер для ручного правила (там же):
> «Add to it when: Claude makes the same mistake a second time»

**A2. `/doctor prompt-audit` — офіційна перевірка «чи не застаріли правила»** · [першоджерело] · URL: той самий
> «Claude looks for problems such as instructions written for older models, references to files or commands that don't exist, and files that contradict each other… `/doctor prompt-audit` requires Claude Code v2.1.283 or later.»

Це найближче до «перевіряє, чи помилка повторилась» з коробки — але це аудит **суперечностей і застарілості правил**, а не детекція повтору самої помилки. Різницю варто тримати в голові.

**A3. Обмеження розміру (важливо для «self-improving CLAUDE.md»)** · [першоджерело]
> «Size: target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence.»

Висновок-ризик: будь-який авто-дописувач правил без дедупу/видалення через кілька тижнів сам собі шкодить.

### D. Суміжне: як вимірюють «менше повторів»

**D1. Метрики, які хтось уже формалізував** · [першоджерело, дизайн-док особистого репо] · дата `2026-02-25` · URL: https://raw.githubusercontent.com/shenxingy/Clade/refs/heads/main/docs/archive/2026-02-25-self-improving-system.md
> «Correction rate = corrections / total user messages (lower = better)»
> «Rule trigger rate = times a correction matches an existing rule domain (lower = rules working)»
> «candidate → validated: Rule survives 7 days without contradiction, triggered 2+ times»
> «Max 50 rules in rules.md (FIFO eviction already exists)»

Це не продукт, а план — але це найкоректніше визначення «чи помилка повторилась» серед усього знайденого, і його можна взяти як мірило для будь-якого інструмента зі списку.

## Висновок

**висновок:** запит «поправка → постійне правило → перевірка, чи повторилось» **закривається з коробки лише наполовину**. Нативний Claude Code дає `auto memory` + `/doctor prompt-audit`, і цього достатньо для 80% болю, якщо ти готовий раз на тиждень чистити файли (і тримати їх <200 рядків — інакше авто-дописування погіршує слухняність).

**висновок:** серед сторонніх інструментів **жоден не має незалежних вимірів «менше повторів до/після»**. Є три самоописи з методологією: `mimir` (WARM/COLD з ε-gate — найчесніший), `agent-recall` (спостереження «0 органічних recall за 44 проєкти»), `auto-sop`/`claude-learner` (метрики є, але вони або у вендорському дашборді, або без даних). Усе інше — маркетинг.

**висновок:** архітектурно правильна зв'язка — **хук на `PostToolUseFailure`/`UserPromptSubmit` (детермінований запуск) + локальний ledger із лічильником + ескалація в `PreToolUse` хук, коли поріг перейдено**. Це рівно те, що робить `cc-retrospective-learner` (Lv.2 → Lv.3 skill/Hook) і частково `claude-evolve` (`skillify`). Інструменти, які просто пишуть у `CLAUDE.md`, не вирішують проблему повтору — вони лише переносять її в контекст.

---

## Рекомендація

**рекомендація** (не факт):

- **Базовий шар (нуль ризику):** увімкнути нативний `auto memory` + поставити в звичку `/doctor prompt-audit` перед великими задачами. Це вже покриває «забув, що мені казали».
- **Якщо треба саме детекція повторів:** почати з `claude-reflect` (найбільше зірок уваги в екосистемі, пише і в `.claude/rules/`, і в AGENTS.md — не прив'язує до одного агента) **або** `cc-retrospective-learner`, якщо тобі критична саме ескалація «правило → хук після 3-го порушення». Другий — японською і маловідомий, тому читай код перед встановленням.
- **Якщо треба саме пам'ять про помилки (а не правила стилю):** `learned-experience` — найчистіший дизайн (хук на failure + `reinforce` з результатом + локальний SQLite, без ключів API). Версія 0.1.0 — тримай на некритичному проєкті.
- **Якщо потрібні докази ефекту, а не обіцянки:** клонуй `mimir` і запусти `demo_band()` **у себе** — це єдиний спосіб отримати не-вендорське число.
- **Чого не робити:** не став `auto-sop` (телеметрія в хмару + self-updating CLI + підписка) на робочу машину без потреби; не вір «enforced» у текстах — enforced буває тільки `PreToolUse`.
- **Метрика для власної перевірки:** `correction_rate = поправки / повідомлення` і `rule_trigger_rate` за 2 тижні до/після. Якщо після впровадження правила `correction_rate` не падає — інструмент не працює, незалежно від зірок.

- **Дата публікації** більшості npm/PyPI-версій (реєстр показував номер, не дату).
- **Офіційного Anthropic-плагіна** для цього сценарію: у документації є `auto memory` і `/doctor prompt-audit`, але немає «learn from corrections» як окремого плагіна. Можливо, з'явився після мого зрізу — не перевірено.

## Червоні прапорці

1. **«Enforced» без хука.** Будь-який текст «помилка більше не повториться» через `CLAUDE.md` суперечить офіційній документації.
2. **Ріст без обмеження.** Тільки `claude-evolve` (dormant/dead), `claude-learner` (>70% ігнорування → prune) і `cc-retrospective-learner` (пороги + ручне схвалення) мають механізм видалення. Решта — додають.
3. **Авто-дописування без людини.** `auto-sop` і `claude-evolution` (авто-промоушен при confidence≥75%, mentions≥5) пишуть у `CLAUDE.md` самі → прямий канал **persistent prompt injection** через текст поправки.
4. **Телеметрія/самооновлення:** `auto-sop` (агрегована статистика в хмару, self-update з npm registry). Ланцюг постачання.
5. **Майже нульове впровадження:** `claude-learner` — 2 завантаження/тиждень; `retrospect` — 0 зірок, без ліцензії. Код не перевірений спільнотою, а хуки виконують довільні команди.
6. **Ризики, названі стороннім оглядом:** «feedback poisoning, memory poisoning, prompt injection, skill bloat» — [третя сторона, https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/docs/resource-evaluations/self-improve-skill.md, дата 2026-01-24]. Сам огляд — приклад того, як легко «знайти» неіснуючий репозиторій.
7. **`fixmind` ≠ правила для агента:** його основний цикл — тестування **тебе** (spaced recall). Легко встановити й отримати не те, що очікував.
