Решта — про розмір: «один grep», «одна перевірка», «дописування записів», «крок скіла», «готую бриф під-агенту».

## 2. Що ворота не бачать
- agents_check: `if agent or n < AGENTS_N or not is_read(...)` — один Agent будь-де в ході вимикає ворота до кінця ходу (сліпих читань: 6b — 1+22+20, 2487 — 51).
- Хід = справжнє повідомлення людини (is_real_user: content-рядок). Сповіщення злито (merge_notifications=True), queued_command не рахується → хід 2487 = 95 викликів.
- Deny лише на виклику-читанні; Write/Edit, python3-скрипти, git, tmux/DSH, delegate, AskUserQuestion не рахуються й не зупиняються.
- Read/Grep/Glob не потрапляють у хук: matcher "Edit|Write|MultiEdit|Bash" (settings.local.json:161); у лічильник з журналу Read іде.
- `cat >> f <<EOF` (дописування) рахується як «читання» (RE_READ_BASH ловить cat).

## 3. Місце народження і правки (без нових воріт)
Місце: edit-gate-hook.py agents_check, рядки 359–363 (`agent` = «був Agent у ході») і межа ходу з answer-gate iter_turns.
П1. Лічити читання від ОСТАННЬОГО Agent, не «чи був Agent у ході»; ключ — сегмент після Agent.
    Сим: 6b 1→2 deny (+10:23:57 закриття сесії, друк baton — хибний), 2487 1→4 (14:37:52, 14:45:10 звірка цитат скілом — напівхибний, 14:54:21 бектест — влучний); останні два ДО докору 14:55:54.
П2. Лічити «роботу» (Bash/Write/Edit/delegate/Skill) замість лише читань і зупиняти будь-який такий виклик. Сим: ті самі 2 і 4 deny, на 5–10 с раніше; докір 08:04 (8 од.) не ловить.
П3. Людське queued_command з шаблоном Р9 (агент…/робиш сам) → deny на наступному виклику з пропозицією Agent. Ловить усі 3 докори, але ПІСЛЯ них (рецидив, не профілактика). Хибних — 0 за двома сесіями [не перевірено на інших].
Білий список причин сам нічого не змінює (сим: ті самі числа), бо причина не несуча.
Не закрито нічим: 08:04 — перевірка звіту під-агента кодом, яку вимагає правило «числа делегата перевіряти кодом» (конфлікт правил).
