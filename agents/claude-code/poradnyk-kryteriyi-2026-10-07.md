# Порадник: критерії для задач (чернетка, 2026-10-07)

Правило користувача (2026-10-07): «потрібні критерії для великих і маленьких задач,
щоб не було на око ніде і ніколи». Отже критерій є в КОЖНОЇ задачі; від розміру
залежить лише, скільки в ньому пунктів. (DSH радив для дрібних питань без критеріїв —
користувач вирішив інакше: мінімум один рядок «Доказ:».)

## Розмір задачі → що записати ДО старту

| Задача | Що записати | Приклад з проєкту |
|---|---|---|
| Мала: одна дія або команда | `Доказ:` — команда і що вона має показати | ярлики DSH: `ls -la` з Termux → `-rw`, `git status` їх не показує |
| Середня: кілька кроків, правка файлів | Доказ + Провал + Хто перевіряє | правка вузла дерева: `git diff` лише додає, назва вузла з джерела |
| Велика / аудит | Доказ + межа обсягу + хто перевіряє + проміжні ворота | аудит «що працює вхолосту» |
| Проба на кілька сесій | Доказ успіху + провал + умова зупинки («якщо до X не сталося Y — зупиняємо») + хто + коли оцінюємо | пам'ять-граф: 3 сесії, критерій у файлі правила |
| Порядок черги | залежність «ДО/ПІСЛЯ X» → що втратимо, якщо не зробити цього тижня → менша задача перед більшою | без числових балів |

## Чотири питання (для середніх і більших задач)
1. **Доказ:** що саме покаже, що зроблено, — вивід команди, файл, цитата. Не «виглядає добре».
2. **Провал:** що вважатимемо невдачею. Записати до старту, а не після.
3. **Хто перевіряє:** не той, хто робив. Самозвіт агента — не доказ (тест v3, G2).
4. **Зупинка:** коли припиняємо спроби й повертаємось до користувача.

## Чого не робити
- Числових балів із дробами — порядок перевертається від зміни шкали
  (Steele 2009, Dawes 1979 — звіт DSH, §4.4).
- «Працює», «готово», «перевірено» без запуску в цій сесії.
- Мовчки міняти критерій після старту — лише з записом і словом користувача.
