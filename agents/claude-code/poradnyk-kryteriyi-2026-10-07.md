# Порадник: критерії для задач (чернетка, 2026-10-07)

Правило користувача (2026-10-07): «щоб не було на око ніде і ніколи». Уточнення
користувача того ж дня: якщо малі задачі йдуть без повних критеріїв, то й сам поділ
«мала / велика» має робитись за критеріями, а не на око. (Моє попереднє прочитання
«критерії скрізь, DSH відхилено» — неточне, виправлено тут.)

## Як визначити розмір задачі — перевірними ознаками, не на око

Відповідаєш так/ні ДО старту; рахується з плану дій, а не з відчуття.

**Велика**, якщо хоч одне «так»:
- зачіпає правила, хуки, налаштування, AGENT.md (RULES.md «Правило 4»);
- незворотне або назовні: видалення, push, платний виклик, лист іншому агенту
  (RULES.md «Структура промпту» — перелік деструктивних дій);
- аудит, порівняння варіантів або проба на кілька сесій;
- не закінчиться в цій відповіді (переходить через сесію).

**Мала**, якщо ВСЕ «так»:
- лише читання, або дописування в 1 файл, що відкочується git;
- 1–2 команди;
- без грошей і без дій назовні;
- закінчиться в цій відповіді.

**Середня** — усе інше.

Мала задача — без повного набору критеріїв, але з одним рядком «Доказ:».
Уже наявні вимірні пороги в проєкті: хук request-brief-reminder рахує «короткий
запит» як ≤12 слів, «нетривіальна правка» — ≥300 символів або ≥5 рядків
(.claude/hooks/request-brief-reminder-hook.py:14-16). Чи вбудовувати ознаки в хук —
окреме рішення після проби.

## Розмір задачі → що записати ДО старту

| Задача | Що записати | Приклад з проєкту |
|---|---|---|
| Мала (за ознаками вище) | `Доказ:` — команда і що вона має показати | ярлики DSH: `ls -la` з Termux → `-rw`, `git status` їх не показує |
| Середня | Доказ + Провал + Хто перевіряє | правка вузла дерева: `git diff` лише додає, назва вузла з джерела |
| Велика: аудит | Доказ + межа обсягу + хто перевіряє + проміжні ворота | аудит «що працює вхолосту» |
| Проба на кілька сесій | Доказ успіху + провал + умова зупинки («якщо до X не сталося Y — зупиняємо») + хто + коли оцінюємо | пам'ять-граф: 3 сесії, критерій у файлі правила |
| Порядок черги | залежність «ДО/ПІСЛЯ X» → що втратимо, якщо не зробити цього тижня → менша задача перед більшою | без числових балів |

## Чотири питання (для середніх і більших задач)
1. **Доказ:** що саме покаже, що зроблено, — вивід команди, файл, цитата. Не «виглядає добре».
2. **Провал:** що вважатимемо невдачею. Записати до старту, а не після.
3. **Хто перевіряє:** не той, хто робив. Самозвіт агента — не доказ (тест v3, G2).
4. **Зупинка:** коли припиняємо спроби й повертаємось до користувача.

## Чого не робити
- Числових балів із дробами — порядок перевертається від зміни шкали
  (Steele 2009, Dawes 1979 — звіт DSH, §4.4).
- «Працює», «готово», «перевірено» без запуску в цій сесії.
- Мовчки міняти критерій після старту — лише з записом і словом користувача.
