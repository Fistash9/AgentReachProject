# agents/ — конвенція приватних тек і авторства

> **Захищений файл.** Зміни — лише з підтвердженням користувача (як `RULES.md`).
> Заведено `[dsh, 2026-09-29]` за рішенням користувача.

## Навіщо
З одним проєктом працюють два агенти: **Claude Code** (`BATON_AGENT=claude-code`)
і **DSH** (`BATON_AGENT=dsh`). Спільні файли ведуть історію, але потрібно, щоб
(а) було видно, **хто** зробив зміну, і (б) у кожного було **своє** місце, куди інший не пише.

## Ієрархія

```text
СПІЛЬНІ, ЖУРНАЛЬНІ   (лише дописувати; кожен запис з тегом автора)
  CONTEXT.md  BACKLOG.md  TROUBLES.md  WEEKLY.md  TRASH.md

СПІЛЬНІ, ЗАХИЩЕНІ    (правки лише за особливою процедурою)
  RULES.md  RULES-WHY.md   — правка RULES лише разом із новим записом RULES-WHY
  USER_PROFILE.md          — лише з явним «так/ні» користувача
  agents/README.md         — цей файл

СПІЛЬНІ, З ВЛАСНИКОМ (хто активний — вирішує baton)
  HANDOFF.md  .baton/baton.json  .baton/ledger.jsonl  .baton/history/pass-<N>.json
  trees/*.md

ПРИВАТНІ             (кожен пише ЛИШЕ у свою)
  agents/claude-code/     нотатки, чернетки
  agents/dsh/             нотатки, чернетки, журнал
  agents/deepseek-search/ (уже існує)
```

## Теги авторства
- **Спільні журнальні файли:** кожен новий запис починається тегом
  `— [dsh, 2026-09-29T23:20Z]` або `— [claude-code, …]`. Без тега запис вважається
  неатрибутованим.
- **`.baton/ledger.jsonl`:** тег уже є — поле `agent` у кожному записі (з `BATON_AGENT`).
- **Приватні теки:** тег не потрібен, там один автор.

## Правила безпеки
1. Ніхто не пише в **чужу** приватну теку — це структурна автономія.
2. Спільні журнали — **ніколи** не переписувати й не видаляти старі записи, лише дописувати.
3. Знімки стану (`CONTEXT.md` «Архітектура»/«Поточний фокус», `HANDOFF.md`) —
   власник baton; перезапис лише після показу нового тексту користувачу.
4. `rm`/`mv` — лише після запису в `TRASH.md`.
5. Baton — **естафета, не паралельна робота**: двоє одночасно `baton_pass` не роблять.
   Паралельна робота ведеться у власних приватних теках.
