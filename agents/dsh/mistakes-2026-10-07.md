## 1. Метод (як я це робив, щоб повторити)

Помилки зібрано **не з пам'яті**, а з доказів. Кожен рядок реєстру має `файл:рядок` або
дослівний вивід команди. Порядок:

1. **Історія дій** — `git log --oneline -12`, `git log --since='2026-10-07 00:00'`,
   `git show --stat --format='%h %ad%n%B' <commit>`; трейлери —
   `git log --pretty='%h %ad %s%n  trailers:%(trailers:key=Agent,valueonly)' --date=format:'%Y-%m-%d %H:%M'`.
2. **Стан передачі** — `tail -6 .baton/ledger.jsonl`, `cat .baton/baton.json`,
   `ls -la .baton/history/`.
3. **Що закомічено, а що ні** — `git status --short`; окремо `git log --since='<час передачі>'`.
4. **Звіти верифікаторів** — повідомлення комітів-виправлень (`fix(...)`), вони самі
   називають знайдене й тим фіксують клас помилки.
5. **Логи й транскрипти** — `.claude/logs/*.jsonl`, `~/.claude/projects/<проєкт>/*.jsonl`
   (зокрема пошук дослівного тексту помилки: `grep -n '<текст>' <файл>.jsonl`).
6. **Наявні механізми** — `ls tools/`, `head` скриптів і хуків, `cat .claude/settings.local.json`.

Правило методу: **немає `файл:рядок` або виводу — немає рядка в реєстрі**. Твердження без
доказу не додається навіть якщо «всі знають».

## 4. ЗАПОБІЖНИКИ

Головна частина. Правило для кожного класу: **що робити** + **де воно живе** + **яка
команда перевіряє** + **скільки коштує**. Усі правила — на одну команду, інакше їх не
виконуватимуть.

### 4.3. Мінімальний набір, який закриває скаргу користувача

Скарга була про **число без опори** (клас б). Найдешевша пара, що ловить клас ДО шкоди:

1. **П2** (число = команда + повторний прогін верифікатором) — 1 команда.
2. **П3** (зведення друкує скрипт) — 1 команда.
3. **П1/П6** (паспорт факту + сторона, яка бачить) — 0 коду, лише правило.
