# DSH — хто це, де його файли, як з ним працювати

> **Для Claude Code** (і будь-якого агента в цьому проєкті). Покажчик на цей файл є в
> `RULES.md` → «Агенти в проєкті». Змінює **лише DSH**.
> Заведено `[dsh, 2026-09-30]`.

## 1. Хто це
**DSH** (DeepSeek Harness) **0.2.0-rc.2** — **окремий агент**, не під-сесія Claude Code.
Живе в Ubuntu через `proot-distro` на тому самому телефоні, **не в Termux**
(у Termux DSH не ставиться через glibc-runner — `TROUBLES.md` #02 лишається чинним).
Модель — `deepseek-flash` через офіційний DeepSeek-провайдер. Свої дані тримає в `/root/.dsh`
(профілі `web` — веб-інтерфейс, `tui` — термінальний).

## 2. Де його файли

| Що | Шлях | Хто пише |
|---|---|---|
| Приватна тека й нотатки | `agents/dsh/` | **лише DSH** |
| Його журнал (дописування) | `agents/dsh/JOURNAL.md` | лише DSH |
| Його інструкції | `/root/.dsh/AGENTS.md` (у proot) | лише DSH |
| Спільні журнали | `TROUBLES.md`, `BACKLOG.md` | обидва, **лише дописування** з тегом автора |
| Baton | `.baton/`, `HANDOFF.md` | обидва, але **естафетою** |

У чужі приватні теки DSH **не пише** — і очікує того самого взамін.

## 3. Що він уміє
- читати й писати файли, зокрема **Termux-теку** через `/data/data/com.termux/files/...`
- запускати shell — **але** на цьому хості пісочниця недоступна, тож **кожна команда потребує
  явного дозволу користувача** (це не примха, а стан середовища)
- веб-пошук і завантаження сторінок; працює з git
- під-агенти — для паралельних досліджень (платно, як і сама сесія)
- **MCP-клієнт**: підключається до тих самих MCP-серверів (зокрема `baton`)

## 4. Чого він **не** вміє — і чому це важливо
- **Він не MCP-сервер.** Його **не можна викликати як інструмент** із Claude Code.
  Обмін — **через baton і файли**, а не «клік → відповідь».
- **Він не під-сесія.** Окремий процес і окрема сесія; спільна лише пам'ять у файлах.
- `claude` із proot **не запускається** (`native binary not installed`).

## 5. Як з ним ефективно працювати
1. **Задачі — через baton, не словами.** `baton_pass` з полем `next` (конкретні кроки) і
   `handoffNote` (де зупинились і чому). Він на старті робить `baton_pick_up` і бере їх звідти.
2. **Одна задача = мета + критерій зупинки** (`RULES.md:22-27`). Без критерію він не знає,
   коли зупинитись і що вважати готовим.
3. **Тег автора обов'язковий** у спільних файлах: `— [dsh, 2026-09-30T01:00+0300]` /
   `— [claude-code, …]`.
4. **Не писати в `agents/dsh/`** і не редагувати `/root/.dsh/AGENTS.md`.
5. **Не переказувати задачу словами**, якщо вона вже в baton — він її прочитає.
6. **Платне — спершу питати користувача** (обидва агенти на платних моделях).
7. **Ті самі критерії якості:** доказ на кожне твердження, рівні Sourced / `[unverified]` /
   Hallucinated — DSH працює за тими самими `RULES.md`.
8. **Після своєї частини — `baton_pass`**, а не «лишити в чаті»: усе, що не у файлі,
   для наступної сесії не існує.

## 6. Обмеження естафети (чесно)
Baton — **естафета, а не паралельна робота**: активний один. Якщо обидва агенти зроблять
`baton_pass` одночасно, стан може перезаписатися — **блокування протокол не має**.
Паралельна робота — лише у власних приватних теках.

## 7. Корисне, що вже перевірено (щоб не шукати заново)
- Termux-ФС видима з proot; proot **виконує** Termux-бінарник `node`, але **не** `claude`.
- `find -type f` **і** `glob` дають хибний тип для частини файлів у `~/.dsh` →
  перевіряти існування через `find -name`, `ls -la`, `stat`.
- pnpm у профілях падає з `ERR_PNPM_IGNORED_BUILDS` → лік: `strictDepBuilds: false` +
  `ignoredBuiltDependencies` у `pnpm-workspace.yaml` профілю (скрипти при цьому не виконуються).

## 8. Коли кликати мене, а коли Claude Code (домовленість 2026-09-30)

Слова користувача: «Буду сюди давати роботу, якщо Клоду буде потрібна допомога, або ти
краще будеш справлятись із задачами». Тобто я — **друге підсилення, не заміна**: маршрут
задачі вибирає користувач, а не агент.

**Краще мені:**
- довгі аудити по файлах і **журналах сесій** (`.jsonl.zstd`, `git blame`, `ps`/`ss`) —
  30.09 витягнув 18 листів із журналу на 2286 подій;
- усе, де потрібен «сирий» proot: Beads (`bd`), конфіги `dsh`, `/root/.dsh`,
  `/root/shared-tree`;
- багатошарова **звірка замість пам'яті** (кожне твердження — з виводу команди);
- картки, дерева, нотатки в Beads;
- відео-аналіз (вузол T7) — після «приймальні».

**Краще Claude Code:**
- робота через його MCP (`transcriptor`, `delegate`, `memory`, `pkgtruth`) — у мене їх немає
  (хостований `transcriptor` можу підключити так само, як підключив `baton`);
- Termux-специфічні прогони (`yt-dlp`, `whisper` — у нього вдома).

**Що змінилося 30.09:** у моїй сесії **немає кліків** (`danger-full-access` + `approval: never`).
Тобто старий аргумент «у DSH кожна команда чекає підтвердження» більше не діє — довгі
механічні ланцюги мені тепер дешевші, ніж були.

**Межа, яку варто пам'ятати:** мій набір інструментів — не його. MCP у мене лише ті, що
в профілі `web` (зараз `baton`), а Termux-шляхи видно тільки тому, що proot неізольований —
у пробному DSH (`--isolated`) їх немає.

## Прямий канал до claude-code (проба 2026-09-30)

> Домовленість між **dsh** і **claude-code**. Записано — [dsh, 2026-09-30T01:38+0300] за дозволом користувача.
> У claude-code своя половина: `agents/claude-code/dsh-direct-channel.md`.

**Схема:**
- claude-code → dsh: `POST http://127.0.0.1:3080/api/session/prompt` (cookie з токена);
- dsh → claude-code: `curl -s -m 5 -X POST http://127.0.0.1:8799/` — слухає Termux,
  **лише поки сесія claude-code відкрита**;
- перевірено наживо: дзвінок → `HTTP 200`, обидва боки працюють.

**Правила обміну:**
- Кожен лист несе **тег агента + час + id**. Мій тег — `[dsh]`, його — `[claude-code]`.
- **Доставка:** не-200 або таймаут = **НЕ доставлено**. Не вважати надісланим; можливі
  дублікати — тому `id` обов'язковий.
- Відповідати **лише на пряме питання**; не більше **3 обмінів** на одну тему.
- Слово **«СТОП»** завершує обмін — далі мовчати (перевірено: на лист зі «СТОП» я не відповів).
- 8799 не відповідає = claude-code **спить** → лист у нотатку Beads (`tree-qis`) або файл,
  **без повторів наосліп**.
- **Гігієна токена:** cookie з 3080 не потрапляє ні в команди, ні в логи. Причина: claude-code
  читає мій журнал сесії з диска, тож усе, що там опиниться, для нього відкрите.

**Чого ця схема НЕ дає (важливо):**
- **Автономії.** Кожна моя команда потребує кліку користувача — «жива» розмова насправді
  гейтована. Канал ≠ автономія; спершу треба пісочницю (`bubblewrap`/`Landlock`), інакше
  кожна дія чекає підтвердження.
- **Авторства в журналі.** Його листи приходять у мою сесію **як від користувача** — тому тег
  у тілі листа не косметика, а єдиний спосіб відрізнити автора.

**Що лишається `[unverified]`:** чи будить completion-notice **закриту** сесію; поведінка
FIFO/сокета в proot; чи дасть `claude mcp serve` із proot кращий канал (нативний бінарник
на місці — 233 МБ `bin/claude-native`, але launcher його не знаходить із proot).
